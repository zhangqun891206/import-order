# 大模型调用说明

> 对应提交要求「大模型调用说明：说明使用的模型、Prompt 设计思路、API Key 配置方式」。
> 代码位置：`lib/ai/deepseek.ts`（调用封装）、`lib/ai/prompt.ts`（Prompt）、`lib/ai/schema.ts`(IR 摘要)、`app/api/rules/ai-generate/route.ts`（入口）。

## 一、使用的模型

| 项 | 值 |
|---|---|
| 模型 | DeepSeek `deepseek-chat`（可由 `DEEPSEEK_MODEL` 覆盖） |
| 协议 | OpenAI 兼容协议 `POST {DEEPSEEK_BASE_URL}/chat/completions`，默认 `https://api.deepseek.com` |
| 参数 | `temperature=0.2`（低随机、输出稳定）、`max_tokens=4096`、`stream=false` |
| 超时 | 60s（AbortController 熔断），超时抛 `DeepSeekError` |
| 调用位置 | 仅服务端 Route Handler；前端不持有 Key、不直连模型 |

**职责边界**：大模型只用于「生成解析规则草稿」（V2 辅助建规则），**不直接解析业务数据**，也**不在导入主链路上**——导入/解析/写库不依赖大模型，AI 失败可降级为手动配置规则，不影响主流程成功。AI 耗时不计入 10,000 单/分钟指标。

## 二、Prompt 设计思路

采用「System 约束 + User 输入」两段式，核心是把模型收敛为**规则配置专家**而非自由问答：

1. **输出强约束**：System 要求"只输出一个合法 JSON 对象"，并给出完整 JSON Schema（layout 五种形态 + fields 来源种类 + target 枚举），从源头降低格式错误。
2. **通用性约束**：禁止针对特定文件名判断；列定位优先表头文本匹配（headerMatch）而非列号，保证规则可复用到同类文件。
3. **置信标注**：要求对每个字段映射在 `fieldMeta` 标 `{inferred, note}`，`inferred=true` 表示推测、需用户确认。前端据此显示「AI 推测」徽标，把最终决定权留给人。
4. **结构引导**：告知干扰头部用 `headerLocate`+`skip` 处理、散落收货信息用 `labelValue` 提取、收货信息 A/B 组二选一，让模型产出贴合规则引擎语义。
5. **User 输入=文件结构摘要**：不喂原始文件/全量数据，而是 `summarizeIR` 压缩出的结构摘要（Excel 各 Sheet 前/尾非空行带坐标、文本前/尾行），既控制 token 又保留足够结构信息。
6. **稳健解析**：`extractJson` 兼容 ```json 围栏与前后杂文，截取首 `{` 到末 `}` 再 `JSON.parse`；失败返回 502 并提示用户手动配置（降级路径）。

设计取舍：让 AI 产出"可执行、可编辑、可版本化"的规则配置，而非一次性解析结果——结果可复现、可人工修正、可复用，且解析执行由确定性引擎完成。

## 三、API Key 配置方式

- 环境变量（不入库、不下发前端）：
  - `DEEPSEEK_API_KEY`：密钥本体
  - `DEEPSEEK_BASE_URL`：默认 `https://api.deepseek.com`
  - `DEEPSEEK_MODEL`：默认 `deepseek-chat`
- 本地：写入 `.env.local`（已在 `.gitignore`，Next 自动加载）。
- 线上：在 Vercel → Environment Variables 配置同名变量；代码通过 `process.env.DEEPSEEK_API_KEY` 读取，缺失时抛错而非静默。
- 安全：Key 只出现在服务端运行时内存；仓库与提交物中不含真实 Key。

## 四、调用链路与降级

```
规则编辑器「AI 分析并生成规则」
  → 前端 summarize(doc) 生成结构摘要
  → POST /api/rules/ai-generate（服务端）
  → chatCompletion(DeepSeek, 60s 超时)
  → extractJson → 校验 spec.layout 存在
  → 返回规则草稿 + fieldMeta（推测标注）
  → 前端两列映射视图人工核对/微调 → 试解析 → 保存
  失败 → 502 + 提示手动配置（不阻塞）
```

## 五、可选扩展（V4）

大模型在 V4 仅作为可选加分项，可用于「错误摘要」（把某批次错误码分布归纳为可读结论）。当前未将其设为必需，保持导入链路对大模型零依赖。
